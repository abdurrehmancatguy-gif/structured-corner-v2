## 3. Standing rules - non-negotiable

These came from the user directly and override defaults. Carry them into every session.

1. **Never push to `main` without consent.** Commit locally, then ask. Every time.
2. **Stay inside this repo.** No sibling repos, no other sites, no borrowed databases.
3. **Never fabricate stats, metrics, or turnaround promises.**
4. **No attribution watermarks anywhere in the code.** No "Generated with Claude", no 🤖,
   no `Co-Authored-By: Claude` trailer in commits. If you find one, remove it.
5. **Don't claim anything.** No superlatives, no unsupported performance claims. If a field
   in `products.json` is empty, the copy must not assert what it would have said.
6. **Do not hardcode images in the site.** Every product image comes from `products.json`.
7. **Keep the copy logical.** Copy must survive a literal reading by a real customer.
8. **No em dashes anywhere in the repo.** Not in copy, not in code comments, not in
   the briefs. Use a hyphen between clauses, or a colon after a label. `&minus;` is
   fine and is not a dash: it is the quantity stepper's decrease control and the sign
   on a negative discount amount. Verify with a repo-wide sweep, not just on the
   generated pages - the one that reached a visitor was built in `shop.js` at runtime
   and never appeared in the HTML.

## 4. How to build and run

### Rebuild the site (do this after ANY content or template change)

```bash
cd /Users/ajoomama/github/structured-corner-v2/flow && python3 build.py
```

It prints `catalogue: 34 products` and `wrote 11 pages`. It must be run **from inside
`flow/`** - it uses relative paths (`content/`, `assets/`).

### Run it locally

The preview server is configured in `.claude/launch.json` as **`bgs-flow`** on **port 4310**.
In Claude Code, start it with the Browser pane (`preview_start` with `{name: "bgs-flow"}`),
never with a raw Bash background process.

Manual equivalent, no-cache:

```bash
cd /Users/ajoomama/github/structured-corner-v2/flow && python3 server.py 4310
```

Then open `http://localhost:4310`.

### Cache-busting

`build.py` stamps a `?v=` token onto `flow.css`, `shop.js` **and** `catalogue.js`. The token
is an md5 of all three files concatenated. **Always edit the assets first, then rebuild** -
rebuilding before the edit leaves the browser on the old module.

## 5. Architecture

### The generator - `flow/build.py`

A single Python script. Structure:

| Region | What it does |
|---|---|
| `esc`, `I`, `P`, `sv` | HTML escaping and an inline-SVG icon dictionary (`P`) |
| `load_content()` | Reads all five JSON files from `content/` into `C` |
| `published(cat)` | Filters products by `published` flag and category |
| `header_logo()`, `favicon_links()`, `footer_logo()` | Driven by `settings.brand` |
| `shell(...)` | The page chrome - header, nav, footer - wraps every page body |
| `card(...)`, `_cards(cat, n)` | Product-card markup + the five category helpers |
| `home`, `collection`, `product`, … | One function per page, each returns a body string |
| `emit_catalogue()` | Writes `assets/catalogue.js` → `window.BGS_CATALOGUE` |
| `PAGES` (line ~1017) | The list of 11 pages; the loop at the bottom writes them |

**Python `%`-format trap.** Several templates are `%`-formatted and several are not.
`%%` only escapes to `%` inside a string that is actually `%`-formatted. A plain string
containing `%%` renders `%%` literally to the user. This shipped to production once
("Includes VAT at 5%%" on checkout). If you add a percentage sign, check which kind of
string you are in.

### The client - `flow/assets/shop.js`

Vanilla JS, no build step, ~17 self-contained IIFEs. Each is independent; one throwing does
not kill the others. Order in file:

1. Quantity steppers
2. Cart totals (`recalc`, exported as `window.BGS_RECALC`)
3. Language toggle
4. PDP renderer - reads `window.BGS_CATALOGUE`, fills story, gallery, notes, ingredients
5. Collection renderer
6. Mobile filter drawer + sticky buy bar
7. Sticky buy bar
8. Hero carousel (autoplay + swipe)
9. Scent quiz
10. PDP gallery (thumbnails, arrows, keyboard, swipe, autoplay)
11. PDP above-the-fold sizing
12. Size chips → variant
13. Collection filter engine (the big one, ~150 lines)
14. Wishlist hearts (`bgs_wish`)
15. PDP tabs
16. Checkout payment method
17. SEO - keeps faceted URLs out of the index
18. Track order + corporate enquiry
19. Gift box builder
20. **Cart - real localStorage state** (`bgs_cart`), ~160 lines at the end of the file

### The styles - `flow/assets/flow.css`

Light theme. Tokens at the top:

```css
--primary:#a8791e; --secondary:#171310;
--ink:var(--secondary); --body:#4a423a; --mut:#6b6154; --faint:#726858;
--line:#e6e0d6; --hair:#f0ece4;  --bg:#fff;      --alt:#faf7f2;
--gold:var(--primary); --gold-d:#8a5a14; --gold-l:#f6efdd;
--red:#b3261e;  --green:#2e6b3e;  --blue:#2b5b7a;
--r:3px;
```

Plus eight fragrance-family colours (`--f-oud`, `--f-amber`, … and `--f-bak`, declared
lower down in a second `:root`), each with a paired `--w-*` wash.

The file is **append-only in practice** and carries duplicate-selector debt. See §9 for the
specificity trap this creates.

#### Brand colours

Two roles, and they are the record. Every other name in `:root` is a *use*, so a change to
the brand should be made against `--primary` / `--secondary`, not against `--gold` / `--ink`.

| Role | Token | Hex | What it carries |
|---|---|---|---|
| **Primary** | `--primary` | `#a8791e` | The only hue in the mark. The whole vocabulary of emphasis: strip countdown, "see all" links, stars, meters, progress fills, nav underline, bag bubble, wishlist on-state, focus rings, promotional CTAs. |
| Primary, text form | `--gold-d` | `#8a5a14` | Wherever the primary has to be small text. |
| **Secondary** | `--secondary` | `#171310` | The structural dark: body text, the delivery strip, the footer, every solid button (Add to bag, Checkout, Place order), the outline-button border, and the "this one is selected" state. |

Measured contrast (sRGB relative luminance):

| Pairing | Ratio | |
|---|---|---|
| `--gold-d` on white | 5.91:1 | passes AA body |
| `--primary` on white | **3.88:1** | large text and non-text only - this is why `--gold-d` exists |
| `--secondary` on white | 18.47:1 | |
| `--secondary` on `--alt` | 17.28:1 | |
| `--secondary` on `--primary` | 4.77:1 | the gold button's own label |
| white on `--secondary` | 18.47:1 | |
| strip text `#e8e2d8` on `--secondary` | 14.34:1 | |
| footer text `#b9b0a4` on `--secondary` | 8.63:1 | |

The footer is the clearest statement of the pair: `footer{background:var(--ink)}` is the
ground that `logo-gold-light.png` sits on, and that file is generated from the *ON_DARK*
ramp in `tools/make_gold_logo.py` specifically for it. Gold mark on the secondary ground.
The ramp itself runs from 3.12:1 at its two end stops up to 15.54:1 at its crest - fine,
because WCAG 1.4.3 exempts logotypes, not because every stop clears AA.

**Two accepted duplicates of the secondary, both deliberate:**

- `--f-res:#171310` stays a literal. Reserve equals the secondary *by value, not by role* -
  it is one of the eight scent-family tokens and has a paired wash `--w-res:#e6e3dd`.
  Aliasing it to `var(--secondary)` would couple brand hierarchy to scent taxonomy, so
  changing the secondary would silently repaint the Reserve tile (`flow.css:654` and `734`)
  and the inline background `build.py` writes into `index.html`, while `--w-res` would not
  follow.
- `INK = (23, 19, 16, 255)` in `tools/make_favicon.py` - a build tool, no CSS to read.

**The older briefs are stale on colour.** `UNDERSTANDING.md:70` gives Reserve as `#26221D`,
`UNDERSTANDING.md:57` gives the ground as `#FAF8F4`, and `FRONTEND-PROMPT.md:95` /
`REBUILD-PROMPT.md:51` disagree on `--mut` and `--faint`. `flow/assets/flow.css:1-16` is
authoritative. Do not build a brand record by copying those tables.

Colours are **not** in `settings.json`. `build.py` reads `settings.brand` only to emit file
paths and alt text and never touches CSS, so colour keys there would be inert data
duplicating the stylesheet.

## 7. Deployment

Both targets serve the **same commit**, from `flow/`.

### Netlify
`netlify.toml` sets `publish = "flow"` with no build command. `_redirects` at the repo root
is a belt-and-braces fallback (`/* → /flow/:splat 200`) for the case where the publish
directory gets overridden in the Netlify UI and the root gets served instead - the root has
no `index.html`, so without it every path 404s.

### GitHub Pages
`.github/workflows/pages.yml` runs on push to `main` (and on manual dispatch). Pages'
"deploy from a branch" option can only serve the repo root or `/docs`, and the site lives in
`flow/` - so the workflow uploads `flow/` as the Pages artifact instead. No build runs in CI;
`build.py` output is committed.

**Open item:** a custom domain `bgs-corner` was entered in the GitHub Pages settings and is
invalid. It needs to be **Removed** in Settings → Pages → Custom domain. Unconfirmed whether
this was done.

## 9. Traps already hit - do not repeat

**CSS specificity, silently.** `flow.css` line ~295 carries `.grid.g5, .grid.g4, .grid.g3`
at specificity (0,2,0). A later rule written as plain `.g4` (0,1,0) **does nothing**, no
matter how far down the file it sits. Write `.grid.gN` to match.

**Selector collision from moving markup.** Moving the notes panel inside `.buy` made
`document.querySelector(".buy p")` match the *Top note* instead of the story - and the note
filler then overwrote every product story on the site. Fixed by selecting `[data-desc]`.
Lesson: `.buy p` style selectors break the moment markup moves. Use data attributes.

**`%%` in non-formatted templates.** See §5. It reached production once.

**Mobile masthead.** The search box's `flex-grow` is what pushes the header actions to the
right on desktop. It is hidden below 900px, so nothing pushes and the bag drifts. Fixed with
`.mast .wrap .acts{margin-left:auto}` plus a badge repositioned to `right:-7px; top:-7px`
(it had been `left:12px` on an 18px element).

**Inline elements can't take a size.** `.circle` is a `<span>`; `width`, `height` and
`border-radius` were all ignored and the category tiles rendered square. Needs
`display:block`.

**Nav that all points to one place.** `nav.main` hrefs carry **no** `?cat=` - every one of
them resolves to `collection.html`. Six links therefore lit up as active at once. Resolve
real destinations via `nav.categories`, which does carry the query strings.

**`sips` zoom-crop.** `-Z size*2` followed by a crop zooms *into* an already-square source.
Use `-Z size`.

**Contrast.** Measured, and both fail WCAG AA: `#C8A86E` as text on white is **2.13:1**;
white on that gold is **2.26:1**. The original brief specified exactly that pairing for
buttons. The shipped palette uses `--gold-d:#8a5a14` for text instead.

**Localhost instability.** Dev servers were repeatedly "stopped by the app" when started as
raw background Bash. Use the Browser pane's `preview_start` with the `bgs-flow` config.

**Chat-pasted images are recoverable.** They live as base64 in
`~/.claude/projects/<slug>/<session-id>.jsonl`. Used twice on this project.
`flow/tools/recover_pasted_velvet.py` is the working example.
