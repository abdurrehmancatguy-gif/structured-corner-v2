## 3. Standing rules - non-negotiable

These came from the user directly and override defaults. Carry them into every session.

1. **Never push to `main` without consent.** Commit locally, then ask. Every time.
2. **Stay inside this repo.** No sibling repos, no other sites, no borrowed databases.
3. **Never fabricate stats, metrics, or turnaround promises.**
4. **No attribution watermarks anywhere in the code.** No "Generated with Claude", no 🤖,
   no `Co-Authored-By: Claude` trailer in commits. If you find one, remove it.
5. **Don't claim anything.** No superlatives, no unsupported performance claims. If a field
   in `products.json` is empty, the copy must not assert what it would have said.
6. **Do not hardcode images in the site.** Every product image comes from `products.json`.
7. **Keep the copy logical.** Copy must survive a literal reading by a real customer.
8. **No em dashes anywhere in the repo.** Not in copy, not in code comments, not in
   the briefs. Use a hyphen between clauses, or a colon after a label. `&minus;` is
   fine and is not a dash: it is the quantity stepper's decrease control and the sign
   on a negative discount amount. Verify with a repo-wide sweep, not just on the
   generated pages - the one that reached a visitor was built in `shop.js` at runtime
   and never appeared in the HTML.

## 4. How to build and run

### Rebuild the site (do this after ANY content or template change)

```bash
cd /Users/ajoomama/github/structured-corner-v2/flow && python3 build.py
```

It prints `catalogue: 33 products` and `wrote 11 pages`. It must be run **from inside
`flow/`** - it uses relative paths (`content/`, `assets/`). It exits with `build failed:` and
a list when a page asks for a file that is not there, a photo's sized copy is missing or was
made from an older photo, or an `.html` in `flow/` is not one it writes (both deploys stop on
that, since every `.html` there is published).

### Run it locally

The store and the admin are one server:

```bash
cd /Users/ajoomama/github/structured-corner-v2 && /usr/bin/python3 admin/server.py
```

Then open `http://localhost:4310` for the store and `http://localhost:4310/admin/` for the
admin. It is one server (`flow/server.py` only launches `admin/server.py`), bound to
127.0.0.1, serving exactly the files the deploys publish, with no-store headers and the
site's own 404 page. The admin has no login yet, which is why it must never listen on
another address. `/usr/bin/python3` has Pillow, which uploads need; films also need ffmpeg
and ffprobe in `/opt/homebrew/bin`. `--no-push` stops the Publish screen from pushing, and
`--storefront-only` serves the store without the admin. See `admin/README.md` for every
screen.

The preview configured in `.claude/launch.json` as **`bgs-flow`** on **port 4310** still runs
`python3 -m http.server 4310 --directory flow`: the store alone, without the admin, the
no-store headers or the site's 404 page. PLAN's step to point it at `admin/server.py` has
not been done. In Claude Code, start it with the Browser pane (`preview_start` with
`{name: "bgs-flow"}`), never with a raw Bash background process. Both use port 4310, so
only one of them can run at a time.

### Run the admin's tests

One file per command, from the repo root, each on its own port:

```bash
ADMIN_RULES_PORT=4741 /usr/bin/python3 -m unittest discover -s admin/tests -p 'test_rules.py'
```

`admin/README.md` lists the 14 files with their port variables. Each runs on a temporary
clone with `--no-push` and never touches `flow/content`.

### Cache-busting

Every asset URL carries `?v=` with the md5 of that one file (`V()` in `build.py`): the pages
load `flow.min.css`, which `build.py` writes from `flow.css`, plus `shop.js` and
`catalogue.js`, each with its own token. Product photos and all their sized copies share the
version of the 1000 px original (`PV()`), salted with `DERIVATIVES`, which has to be bumped
when the copies change without the original changing (a new quality or size).
**Always edit the assets first, then rebuild** - rebuilding before the edit leaves the
browser on the old module.

**After importing photos**, run `python3 tools/make_derivatives.py` from `flow/` before
`build.py`. It writes the sized copies the pages use (`-600`, `-card-360` and `-thumb` for
product photos, 750 and 1320 px banners, 486 px logos, 216 px circles) and removes copies
whose original is gone. It redoes a copy when its source's bytes, or the size and quality,
differ from what `tools/derivatives.json` records; commit that file with the images, because
`build.py` checks the copies against it.

## 5. Architecture

### The generator - `flow/build.py`

A single Python script. Structure:

| Region | What it does |
|---|---|
| `esc`, `I`, `P`, `sv` | HTML escaping and an inline-SVG icon dictionary (`P`) |
| `load_content()` | Reads settings, navigation, copy, home, products and pages from `content/` into `C`; `translations.json` and `quiz.json` are read in their own blocks |
| `RULES`, `RULE_TEXT` | The store rules from `settings.store`, checked, and the words they print. A bad rule stops the build; a missing one falls back to the old value |
| `page_text()`, `js_text()` | `page_text()` prints a content string escaped, filling `{tokens}` where the place allows them; `js_text()` checks a string shop.js will write. Problems collect in `_BAD_PAGES` and stop the build before any file is written |
| `published(cat)` | Filters products by `published` flag and category |
| `header_logo()`, `favicon_links()`, `footer_logo()` | Driven by `settings.brand` |
| `shell(...)` | The page chrome - header, nav, footer - wraps every page body |
| `card(...)`, `_cards(cat, n)` | Product-card markup + the five category helpers |
| `home`, `collection`, `product`, … | One function per page, each returns a body string |
| `emit_catalogue()` | Writes `assets/catalogue.js`: `window.BGS_CATALOGUE`, `BGS_IMGV`, and the globals listed in `EXTRA_GLOBALS` (`BGS_RULES`, `BGS_CATS`, `BGS_COPY`, `BGS_AR`, `BGS_QUIZ`) |
| `PAGES` (line ~1712) | The list of 11 pages; the loop at the bottom writes them |

**Python `%`-format trap.** Several templates are `%`-formatted and several are not.
`%%` only escapes to `%` inside a string that is actually `%`-formatted. A plain string
containing `%%` renders `%%` literally to the user. This shipped to production once
("Includes VAT at 5%%" on checkout). If you add a percentage sign, check which kind of
string you are in. The quiz template became `%`-formatted on 2026-09-12, so a literal `%`
in it has to be written `%%` now.

### The client - `flow/assets/shop.js`

Vanilla JS, no build step, 27 self-contained `bgsRun` blocks. Each is independent; one
throwing does not kill the others. It reads content only through the window globals in
`catalogue.js`: `bgsRule(path, fallback)` for the store rules, `bgsCopy`, `bgsCopyHtml` and
`bgsFill` for page text, `bgsAr` for the Arabic of text written after load, `catText` for
category text, and `BGS_AR` and `BGS_QUIZ`. Each
fallback is the text or number the shop had before, so a missing key falls back to it. The
list below is from before the admin and is kept for orientation. Order in file:

1. Quantity steppers
2. Cart totals (`recalc`, exported as `window.BGS_RECALC`)

9. Scent quiz

specificity trap this creates.

#### Brand colours

Two roles, and they are the record. Every other name in `:root` is a *use*, so a change to
the brand should be made against `--primary` / `--secondary`, not against `--gold` / `--ink`.

| Role | Token | Hex | What it carries |
|---|---|---|---|
| **Primary** | `--primary` | `#a8791e` | The only hue in the mark. The whole vocabulary of emphasis: strip countdown, "see all" links, stars, meters, progress fills, nav underline, bag bubble, wishlist on-state, focus rings, promotional CTAs. |
| Primary, text form | `--gold-d` | `#8a5a14` | Wherever the primary has to be small text. |
| **Secondary** | `--secondary` | `#171310` | The structural dark: body text, the delivery strip, the footer, every solid button (Add to bag, Checkout, Place order), the outline-button border, and the "this one is selected" state. |

Measured contrast (sRGB relative luminance):

| Pairing | Ratio | |
|---|---|---|
| `--gold-d` on white | 5.91:1 | passes AA body |
| `--primary` on white | **3.88:1** | large text and non-text only - this is why `--gold-d` exists |
| `--secondary` on white | 18.47:1 | |
| `--secondary` on `--alt` | 17.28:1 | |
| `--secondary` on `--primary` | 4.77:1 | the gold button's own label |
| white on `--secondary` | 18.47:1 | |
| strip text `#e8e2d8` on `--secondary` | 14.34:1 | |
| footer text `#b9b0a4` on `--secondary` | 8.63:1 | |

The footer is the clearest statement of the pair: `footer{background:var(--ink)}` is the
ground that `logo-gold-light.png` sits on, and that file is generated from the *ON_DARK*
ramp in `tools/make_gold_logo.py` specifically for it. Gold mark on the secondary ground.
The ramp itself runs from 3.12:1 at its two end stops up to 15.54:1 at its crest - fine,
because WCAG 1.4.3 exempts logotypes, not because every stop clears AA.

**Two accepted duplicates of the secondary, both deliberate:**

- `--f-res:#171310` stays a literal. Reserve equals the secondary *by value, not by role* -
  it is one of the eight scent-family tokens and has a paired wash `--w-res:#e6e3dd`.
  Aliasing it to `var(--secondary)` would couple brand hierarchy to scent taxonomy, so
  changing the secondary would silently repaint the Reserve tile (`flow.css:654` and `734`)
  and the inline background `build.py` writes into `index.html`, while `--w-res` would not
  follow.
- `INK = (23, 19, 16, 255)` in `tools/make_favicon.py` - a build tool, no CSS to read.

**The older briefs are stale on colour.** `UNDERSTANDING.md:70` gives Reserve as `#26221D`,
`UNDERSTANDING.md:57` gives the ground as `#FAF8F4`, and `FRONTEND-PROMPT.md:95` /
`REBUILD-PROMPT.md:51` disagree on `--mut` and `--faint`. `flow/assets/flow.css:1-16` is
authoritative. Do not build a brand record by copying those tables.

Colours are **not** in `settings.json`. `build.py` reads `settings.brand` only to emit file
paths and alt text and never touches CSS, so colour keys there would be inert data
duplicating the stylesheet.

### Business rules - `flow/content/settings.json`

The numbers live in `settings.store`. `build.py` prints them and passes them to `shop.js` as
`BGS_RULES`, and the owner changes them on the admin's Discounts and Settings screens. VAT
and COD stay locked in code: the admin refuses a change to them.

| Rule | Value |
|---|---|
| VAT | 5%, **inclusive** - `vat = total − (total / 1.05)`. Never added on top. |
| VAT display | **Checkout page only.** Not on cart, not on confirmation. |
| Free delivery | over AED 150 (else AED 12) |
| Same-day Dubai | +AED 25, cutoff 2:00 PM |
| COD | withheld over AED 300; fee AED 8 |
| Gift box | AED 25; 10% off at 3+ items |
| Volume discount | 10% at 3 items, 15% at 6; never-discounted products excluded |
| Gift with purchase | Mystery oud, 3 ml, over AED 300 |
| Low stock | badge at 5 or fewer |

### The admin - `admin/`

A local back office, never published. `admin/README.md` covers use, `admin/DESIGN.md` the
decisions and extension points, `admin/docs/PLAN.md` the architecture and its status.

- **One server.** `admin/server.py` serves the store preview (exactly the published files)
  and the admin on 127.0.0.1:4310. Every API call needs the per-run token and the right Host;
  a change also needs the admin's own Origin and a JSON body or a typed raw upload.
- **The store is the JSON files.** `bgsadmin/store/jsonstore.py` gives each product and
  document a rev. A save is validated against the schema, checked against the rev and written
  atomically in a transaction that runs `make_derivatives.py` when media changed and then
  `build.py`, and every file is put back byte for byte if the build fails. The previous
  version goes to `flow/content/.backups/`.
- **Schemas drive the forms and the checks.** `bgsadmin/schema/` has one module per resource:
  products and the seven documents (settings, copy, home, navigation, pages, quiz,
  translations). The UI draws its forms from them and the server enforces them, locked fields
  (payments, VAT, COD) and read-only ones included. A new document is a schema module plus
  its file.
- **One API module and one screen per area**, in `bgsadmin/api/` and `ui/screens/`, found
  without a central table. The screens are Home, Products (with Inventory, Bulk editor and
  Import and export), Collections, Homepage, Navigation, Site text, Pages, Scent quiz,
  Translations, Files, Discounts, Publish, History and Settings. Orders, Customers and
  Analytics are switched off until the database.
- **Media.** Uploads go to `.backups/staging`, are checked and re-encoded, and are attached
  in a save that cuts their sized copies. Films are converted in a background job. Files
  nothing uses go to a trash they can be restored from.
- **History and publishing.** History lists local backups and committed versions and
  restores one as a normal save. Publish commits only content, media and generated files,
  with `git commit --only`, after rebuilding the tree in a clean room, and pushes the reviewed
  sha, fast-forward only, after the owner types PUBLISH. It never forces, pulls, merges or
  rebases.
- **Locked in code:** checkout, order confirmed, payments, VAT, COD and the pricing formulas.

## 7. Deployment

Both hosts deploy every push to `main` and publish the same list of files: the eleven pages,
`404.html`, `favicon.ico`, `robots.txt` and `assets/`. The generator (`build.py`,
`server.py`), `content/`, `tools/` and `edp_data.json` are not published.

Before publishing, both rebuild `flow/` and stop if anything differs from what is committed,
new files included (`git status --porcelain`), so a forgotten rebuild never ships. The build
is byte-identical under Python 3.9, 3.12 and 3.13.

### Netlify
`netlify.toml` runs that check, copies the list into `_site` and publishes `_site`, with
`PYTHON_VERSION = "3.12"`. `/assets/*` is cached for a year as immutable and HTML as
no-cache, so every asset URL carries `?v=<content hash>` (`V()` and `PV()` in `build.py`;
product photos share their original's version, passed to `shop.js` in `catalogue.js`).
`_redirects` at the repo root only matters if the root is ever published by mistake: it
refuses `flow/`'s sources, then rewrites everything else into `flow/` (forced, `200!`).

### GitHub Pages
`.github/workflows/pages.yml` runs the same check and uploads `_site` as the Pages artifact.
Pages sends `max-age=600` on everything and ignores query strings when caching. Its terms
rule out running a shop on it (§10), so it should become a browse-only mirror or be retired
once the shop has one host.

The custom-domain item that used to be open here is resolved: Pages reported no custom
domain on 2026-09-10.

## 9. Traps already hit - do not repeat

**CSS specificity, silently.** `flow.css` line ~295 carries `.grid.g5, .grid.g4, .grid.g3`
at specificity (0,2,0). A later rule written as plain `.g4` (0,1,0) **does nothing**, no
matter how far down the file it sits. Write `.grid.gN` to match.

**Selector collision from moving markup.** Moving the notes panel inside `.buy` made
`document.querySelector(".buy p")` match the *Top note* instead of the story - and the note
filler then overwrote every product story on the site. Fixed by selecting `[data-desc]`.
Lesson: `.buy p` style selectors break the moment markup moves. Use data attributes.

**`%%` in non-formatted templates.** See §5. It reached production once.

**Mobile masthead.** The search box's `flex-grow` is what pushes the header actions to the
right on desktop. It is hidden below 900px, so nothing pushes and the bag drifts. Fixed with
`.mast .wrap .acts{margin-left:auto}` plus a badge repositioned to `right:-7px; top:-7px`
(it had been `left:12px` on an 18px element).

**Inline elements can't take a size.** `.circle` is a `<span>`; `width`, `height` and
`border-radius` were all ignored and the category tiles rendered square. Needs
`display:block`.

**Nav that all points to one place.** `nav.main` hrefs carry **no** `?cat=` - every one of
them resolves to `collection.html`. Six links therefore lit up as active at once. Resolve
real destinations via `nav.categories`, which does carry the query strings.

**`sips` zoom-crop.** `-Z size*2` followed by a crop zooms *into* an already-square source.
Use `-Z size`.

**Contrast.** Measured, and both fail WCAG AA: `#C8A86E` as text on white is **2.13:1**;
white on that gold is **2.26:1**. The original brief specified exactly that pairing for
buttons. The shipped palette uses `--gold-d:#8a5a14` for text instead.

**Localhost instability.** Dev servers were repeatedly "stopped by the app" when started as
raw background Bash. Use the Browser pane's `preview_start` with the `bgs-flow` config.

**Chat-pasted images are recoverable.** They live as base64 in
`~/.claude/projects/<slug>/<session-id>.jsonl`. Used twice on this project.
`flow/tools/recover_pasted_velvet.py` is the working example.

- **zsh does not split a variable holding several paths.** `git add $LIST` passes one bogus
  path and the whole add fails; list the paths or use a glob.
- **macOS `unzip` fails on non-ASCII file names with a misleading "disk full?"** and then
  waits at a prompt. Extract with Python's `zipfile` instead.
- **Headless Chrome will not make a window narrower than about 500px.** Render phone widths
  inside an iframe of a wrapper page, or the screenshot is a cropped wider layout.
- **A generated copy must never be taken for an original.** `vibe-1-600.jpg` and
  `banner-1-1320.jpg` both look like frame numbers; `make_derivatives.py` skips them now.
- **`\u` escapes typed into a file-writing tool arrive as the characters.** A validator
  written with an em dash escape in its source ended up holding a literal em dash, which the
  repo rule forbids. Write such characters as `chr(0x2014)` in Python.
- **Workflow agents are dropped after three minutes without progress.** A long browser
  sweep or one very large file write counts as none; tell agents to keep every command under
  two minutes and write files in pieces.
- **Run an admin test file with `discover`.** This form works for every file:
  `python3 -m unittest discover -s admin/tests -p '<file>'`. The files import `box.py` from
  their own folder, so `python3 -m unittest admin/tests/<file>` cannot import them, and
  `test_bulk_ui.py` and `test_publish.py` do nothing when run as scripts.
- **Each admin test file reads its port from its own variable** (`ADMIN_RULES_PORT` and so
  on, listed in `admin/README.md`), with a default between 4731 and 4782. Two runs of one
  file at once collide on its port. Keep test servers on 4700 to 4799; 4310 is the owner's
  preview.
- **Chrome 152 headless `--dump-dom` never exits on this Mac.** It prints the DOM and keeps
  running. `admin/devtools/dom_diff.py` reads up to `</html>` and kills it; any new script
  that dumps a DOM has to do the same, or it hangs.
- **`env(safe-area-inset-*)` is 0 without `viewport-fit=cover`**, which every page but
  404.html now has. Chrome can emulate an iPhone's insets for a check:
  `Emulation.setSafeAreaInsetsOverride` with `{insets: {bottom: 34}}` in portrait or
  `{left: 47, right: 47, bottom: 21}` in landscape, after `setDeviceMetricsOverride` with
  `mobile: true`.
- **Page text read after the `_BAD_PAGES` exit in `build.py` is never checked.** The build
  collects page-text problems and stops just before it writes `catalogue.js`. Read new page
  text above that line.
- **A new generated file needs two lists.** Add it to `publishing.GENERATED` as well as
  `config.generated_files()`, or the Publish screen never commits it. The clean-room check
  runs `build.py` with only `flow/` present, so `build.py` must not read anything outside
  `flow/`.
- **Chrome shows the old picture for a file replaced under the same name, even with
  no-store.** The admin adds a `?v=` token to previews after an upload or a restore
  (`mediaUrl` in `admin/ui/lib/media.js`); use it for any preview of a file that can change.
- **A hidden screen-reader label can widen a page.** Absolutely placed children escape a
  scrolling table's clipping unless the scroll box is positioned; the Bulk editor's
  `.bulk-wrap` is `position:relative` for this reason.
- **`Element.append(null)` prints the word "null".** Leave empty children out before
  appending; the Publish screen showed "null" on an empty card until it did.
- **Key presses in the hidden Browser pane arrive with an empty key.** Keyboard checks there
  prove nothing; drive keys through headless Chrome (`admin/tests/cdp_pipe.py`) instead.

## 11. Resuming - first five minutes

```bash
cd /Users/ajoomama/github/structured-corner-v2
git status && git log --oneline origin/main..HEAD
```

Then start the preview (`bgs-flow`, port 4310) and open `http://localhost:4310`. For the
admin, run `/usr/bin/python3 admin/server.py` instead (same port) and open
`http://localhost:4310/admin/`.

To change anything on the site:

1. Edit content in the admin, which checks, saves, rebuilds and keeps a backup, or edit
   `flow/content/*.json` by hand for **content**, or `build.py` / `shop.js` / `flow.css` for
   **structure, behaviour, or style**.
2. `cd flow && python3 build.py`
3. Reload. Confirm the `?v=` token changed.
4. Commit locally with a message that says what changed and why.
5. **Ask before pushing.**

Never hand-edit `flow/*.html` or `flow/assets/catalogue.js` - both are generated and will be
overwritten on the next build.

Before changing the admin, read `admin/DESIGN.md`, and run the test file for the area you
touched (`admin/README.md` lists them).
