## flow/build.py

build.py builds 11 pages from module-level HTML strings plus a hand-written 404 and robots.txt. Only a small part of what a visitor sees comes from content JSON today: the hero slides and images, the reels, the USP row, the quiz banner, the category circles and catnav, the tab bar, the logos and favicons, og_image, and the product data (via cards and catalogue.js). Almost everything else is typed into build.py. That covers the strip, the search placeholder, the header action labels, the footer (columns, legal line, address slot, newsletter, copyright), every homepage heading and link and its hardcoded counts (All 13, All 9), the Discovery band, the promo tiles and the 8 scent-family tiles, and all the copy on the collection, product, gift-box, cart, track, account, quiz, corporate and 404 pages. SEO titles and descriptions are typed in too. Several content keys already exist with the same text but nothing reads them: copy.strip, copy.search_placeholder, copy.collection_intros, home.sections, navigation.footer (whose hrefs differ from the hardcoded footer), navigation.main, settings.seo.default_title_suffix, settings.brand.suffix, and every settings.store rule except name. social, analytics, payments and languages are also unread, as are 13 product fields. Store rules (150/12/25/2:00 PM/300/8, gift box 25 and 10% at 3, volume tiers 3/6 at 10/15%, gift at 300, low stock at 5) are typed as literals in build.py and again in shop.js, which also overwrites several build.py strings at runtime. Checkout, confirmation and payment displays are marked locked. Customer-facing bugs and unverified claims found along the way: the quiz shows AED 89 while every spray is AED 85; placeholders like '[ address, hours, phone ]', '[ count ]' and 'Banner' are visible to customers; the gift-box intro, the voucher and loyalty copy, the gift options, and the 'every blend is alcohol-free and oil based' line all promise things that nothing implements. A fresh build of the current working tree in a scratch copy reproduced every generated file byte for byte (Python 3.9.6), so that snapshot is the refactor baseline.

### Structural notes

- Execution model: build.py is a script, not a module. Everything runs at import: C = load_content() reads the five JSON files, then each page body (home, collection, product, giftbox, cart, checkout, confirmed, corporate, track, account, quiz) is a module-level triple-quoted string evaluated on the spot, so helpers like attar_cards() run when the string is defined. Then come emit_catalogue(), minify_css(), PRELOAD = product_preload(), the loop that wraps each body in shell(title, body, nav_on, tab, page, desc, canon) and writes PAGES, then 404.html and robots.txt, then _problems(). The admin must run it as a subprocess with cwd flow/ (paths are relative), never import it: importing writes files.
- Two templating styles. (1) %-dict formatting: shell and home, collection, product, giftbox, cart, confirmed, corporate and account end in % dict(...). (2) Plain strings: checkout, track and quiz are not formatted. catstrip() uses str.format ({0}..{4}); the 404 is a literal. The %-trap: inside formatted templates a literal % must be %% (giftbox '&minus;10%%', cart 'width:100%%', 'save 15%%', '</b>%%'), and in plain ones a single % (checkout 'Includes VAT at 5%', quiz 'width:20%'). If the refactor turns a plain template into a formatted one, double every literal %. If it removes cart's otherwise dead % dict(vat=...), turn its %% back into %. Values substituted in are never reinterpreted, so a % in content is safe.
- Helpers: esc() = html.escape(quote=True). I(d,w,s) wraps SVG path data; P is the icon dict (search, user, heart, bag, menu, truck, clock, cash, leaf, drop, chev, filter, home, shop, share, c_gift, left, right, check); sv(k,w,s) = I(P[k]) raises KeyError on an unknown key. copy.usp icons go straight to sv(), so a bad key there crashes the build, while tab_link falls back to the label. The 8 family-tile SVGs are NOT from P (class fic, stroke-width 1.5, stroke-linejoin round, no width/height), so they need their own wrapper to stay byte-identical. slot(label) = <span class=slot>label</span>, and CSS adds '[ ' and ' ]'. money() adds thousands separators and turns a blank into '0'. _meta(pr) builds the per-category meta line. card(), ph_img() (alt escapes only the double quote, not esc()), _cards/_cards_from plus the attar/halo/bakhoor/edp/set wrappers, usp_strip, hero_slides, hero_images, hero_dots, reels, catnav, catstrip, tab_link, facet_live, header_logo/footer_logo/favicon_links, png_size. V(path) returns path?v=<md5[:8]> of the file, or no ?v= if it is missing, and records the result in _VH. PV(name, suffix) versions product photos from the 1000px original salted with DERIVATIVES. CARD_SIZES, FEAT_SIZES and GALLERY_SIZES are duplicated in shop.js. unent() double-unescapes strings for catalogue.js.
- Keep every V()/PV() call running before _problems(): the missing-file check reads the _VH cache those calls fill. A renderer that skips an image or calls V() lazily after the check would hide a missing file. The photo-copy check also walks products.images and tools/derivatives.json, so admin image uploads must run tools/make_derivatives.py (sizes -card, -card-360, -600, -thumb; heroes -1320, -phone, -phone-750) before build.py or the build fails.
- Escaping is inconsistent, and byte identity depends on it. esc() covers hero-slide fields, reel labels and titles, nav/tab/category labels and hrefs, logo alt, favicon paths, desc and canonical. Inserted RAW: copy.usp, copy.quiz_banner (href included), card meta, notes, size labels and price, facet labels, PAGES titles, and every template literal. Templates carry entities (&amp; &middot; &rarr; &rsquo; &hellip; &times; &minus; &larr; &copy;) while content JSON stores literal characters (the middle dot, the ellipsis, &). esc() does not reproduce those entities: it leaves the dot and the curly apostrophe as characters and turns a straight apostrophe into &#x27;. So a byte-identical move has to store the exact HTML fragment, entities and all, and emit it raw (e.g. 'Arm&rsquo;s length', 'Search ouds, oud, bakhoor&hellip;'). Normalising to plain text plus esc() is a second, deliberate commit with a reviewed diff. Examples where esc() happens to match: 'Bakhoor & home' and 'Delivery & returns' both give &amp;.
- Whitespace is part of the output: sections start with a newline and two-space indents, family tiles are separated by a newline and four spaces, the USP divs are joined with ''. The reels block and the home template end without a trailing newline before %(reels)s. A loop-based renderer that replaces hand-written HTML must reproduce the separators exactly; check with cmp, not by eye.
- Byte-identical baseline: copying the current working tree's flow/ to a scratch directory and running build.py with /usr/bin/python3 (3.9.6) reproduced every *.html, robots.txt, assets/catalogue.js and assets/flow.min.css byte for byte (checked 2026-09-11). The working tree has uncommitted edits (navigation.json relabels, flow.css, shop.js, server.py, HANDOFF.md and the rebuilt pages), so the baseline is the working tree, not HEAD. Procedure: snapshot those files, move one group of values, rebuild, cmp each file, then continue. Keep deliberate fixes (footer hrefs from navigation.footer, the '34' count, the quiz price, stale intros, hiding visible slots) in separate commits.

The only content shop.js reads is product data, through window.BGS_CATALOGUE and BGS_IMGV (both written by build.py emit_catalogue()). Every store rule, label, message and data table in it is a literal.

- the bag's volume discount: 10% from 3 items, 15% from 6
- the free mystery oud at AED 300, written twice

- the 20-per-line quantity limit, written five times
- gift box sizes of 3 and 6
