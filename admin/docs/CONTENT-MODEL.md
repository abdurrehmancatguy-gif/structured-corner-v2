# Content model map (2026-09-11)

Content model mapped from the working tree of /Users/ajoomama/github/structured-corner-v2 (branch main). The tree has uncommitted edits to navigation.json, shop.js, flow.css, server.py, HANDOFF.md and the regenerated pages. It still builds clean: a fresh build on a scratch copy with /usr/bin/python3 3.9.6 came out byte-identical, and the repo was not modified.

How the data flows:
- build.py is the only reader of flow/content/*.json (load_content, build.py:76-80).
- shop.js never reads content directly. It only sees window.BGS_CATALOGUE and window.BGS_IMGV, which emit_catalogue (build.py:1137-1178) builds from published products: name, meta, price, pn, cat, crumb, sizes, images, top, heart, base, ing (from ingredients), sku (from barcode), gender, story, stock, halo (from never_discount).

What products.json holds:
- 34 products keyed by id (33 published; seasonal-slot is not), 31 distinct keys in all.
- The real category keys are attars (14), edp (9), gift-sets (6) and bakhoor (5). HANDOFF section 5's oud-oils/reserve keys are stale.
- Wired product fields: name, category, price, stock, gender, size, top, heart, base, ingredients, barcode, story, never_discount, published, order, images, sizes, contents.
- Read by nothing (and empty in all 34 products): name_ar, story_ar, family, tone, occasion, season, longevity, sillage, badge, seo_title, seo_description, image_alt, related.

Also unwired:
- Every settings.store rule. The numbers are hardcoded in shop.js (recalc, gift box, cutoff) and in build.py copy.
- seo.default_title_suffix, and seo.default_description (PAGE_DESC covers all 11 pages, so it is never used).
- social, analytics, payments and languages.
- brand.suffix (only tools/make_gold_logo.py reads it).
- copy.strip, copy.search_placeholder and copy.collection_intros.
- home.sections.
- navigation.main (read into NAV, never emitted) and navigation.footer (the footer is hardcoded in shell()).

Editing any of those in an admin changes nothing on the site until build.py or shop.js is wired to read them. Part of wiring the store rules sits inside the locked cart engine.

What build.py checks: that referenced media exists and that sized copies are current. It does not check value types:
- A decimal or negative price silently becomes AED 0 on the site and in the bag.
- Missing keys or an unknown usp icon crash with a traceback.
- It writes every output before it runs its checks, so a failed build leaves flow/ half-updated.

## Media pipeline

General rules for every upload:
- Everything under flow/assets is published (the deploy copies the whole folder, minus cat/SOURCES.txt and flow.css). Raw uploads and originals must be staged outside flow/, and only the finished files written in.
- Run every tool from flow/ with /usr/bin/python3; Pillow 11.3 and ffmpeg 8.1 are installed.
- HEIC does not open (no pillow_heif installed). Convert it first with sips -s format jpeg.

1. Product frame
- Input: any image Pillow opens (jpg, png, webp).
- Process it exactly like tools/import_website_set.py resize() (lines 133-147): open the image; if its mode is RGBA, LA or P, composite it onto white, otherwise convert to RGB; centre-crop to a square of the short side; resize with LANCZOS.
- Save two files, JPEG quality 72, optimize=True, progressive=True:
  - flow/assets/img/<id>-<n>.jpg at 1000x1000
  - flow/assets/img/<id>-<n>-card.jpg at 520x520
- <n> is the next free integer for that id. The display order is the images[] order, not the file number (FRAME_ORDER in the importer only reorders the list).
- The name must match [a-z0-9-]+-<n>.jpg, all lowercase, must not start with banner-, and must not end -600, -card, -card-360 or -thumb (so n must never be 600).
- Then run: python3 tools/make_derivatives.py. It writes three copies at JPEG quality 78, optimize, progressive: <id>-<n>-600.jpg (600 wide), <id>-<n>-card-360.jpg (360) and <id>-<n>-thumb.jpg (160). It rewrites tools/derivatives.json as sorted JSON, indent 1, with one entry per copy: key "assets/img/<id>-<n>-600.jpg", value ["assets/img/<id>-<n>.jpg", md5 of the original's bytes, "jpeg q78 w600 sNone"]; recipes w360 and w160 for the other two.
- Append "<id>-<n>.jpg" to products.<id>.images. Position 0 is the card, first PDP frame and bag thumbnail; position 1 is the card hover shot, by convention the one with the box.
- Replacing a frame: rewrite both the 1000 original and its -card, then rerun make_derivatives. build.py never checks -card for staleness, so a forgotten -card passes the build and shows the old photo.
- Removing a frame: take it out of images[] and delete the original and its -card. make_derivatives deletes the orphaned -600, -card-360 and -thumb files and drops their manifest entries, but not -card.
- Nothing is edited in catalogue.js by hand. build.py regenerates window.BGS_IMGV, one ?v= per original (md5 of the original plus the salt DERIVATIVES = b"d1", build.py:28), shared by all its copies. If QUALITY or a size in make_derivatives.py ever changes, bump DERIVATIVES too.

2. Hero banner, desktop and phone
- Two separate crops, not one resize:
  - flow/assets/img/banner-<n>.jpg: 2400x790 desktop band, declared 2400w with width 2400 and height 790 (build.py:467-468). The existing files are 124 to 208 KB.
  - flow/assets/img/banner-<n>-phone.jpg: 1110x600, a 1.85:1 crop centred on the product, declared 1110w (build.py:453-465).
- The name must match banner-<digits>.jpg (make_derivatives.py:88).
- Then run make_derivatives.py. It writes banner-<n>-1320.jpg (1320 wide, quality 78, recipe "jpeg q78 w1320 sNone") and banner-<n>-phone-750.jpg (750 wide, recipe "jpeg q78 w750 sNone"), each recorded against its source's md5.
- Reference "assets/img/banner-<n>.jpg" in home.json hero_slides[].image, with an image_alt.
- The build checks that all four files exist and that both manifest entries match. seo.og_image currently uses banner-1.jpg.
- tools/import_images.py banner() is a one-off composite for banner-1 (quality 84), not the general route.

3. Category circle, photo
- Save the source as flow/assets/cat/<key>.jpg: any size (the existing ones are 420x240), JPEG, name not ending -216. PNGs are not processed.
- make_derivatives.py centre-crops it square and resizes to flow/assets/cat/<key>-216.jpg (216x216, quality 78, recipe "jpeg q78 wNone s216"), recording it in the manifest. It deletes a -216 copy whose source is gone.
- navigation.json: categories[].image = "assets/cat/<key>-216.jpg", with cutout absent or false.
- The build checks existence and manifest freshness.

4. Category circle, cut-out
- A PNG with real alpha. Three of the four supplied had checkerboards painted into RGB pixels that had to be keyed out.
- Trim it to the object and normalise it onto a 204x240 transparent canvas, standing on the bottom edge like the existing four. Quantise to 256 colours (the existing files are mode P, 7 to 21 KB).
- Save as flow/assets/cat/<key>.png and set categories[].image = "assets/cat/<key>.png" and "cutout": true.
- No copy is made and nothing goes in the manifest. The build checks existence only.
- Record provenance in assets/cat/SOURCES.txt (not published).

5. Logo
- The masthead art is flow/assets/img/logo-gold.png and the footer art is logo-gold-light.png: full-size RGBA lockups, currently 3149x505, the light one using a lifted ramp for the dark ground.
- Either upload transparent PNGs under exactly those two names, or regenerate them with python3 tools/make_gold_logo.py. That tool draws settings.brand.suffix onto assets/img/logo.png and needs the macOS Bodoni 72 font, which is present.
- Then run make_derivatives.py. It writes logo-gold-486.png and logo-gold-light-486.png: 486 wide, premultiplied LANCZOS resize, FASTOCTREE 256-colour quantise, recipe "png w486". Only those two base names get a copy.
- settings.brand.logo and logo_light already point at the -486 files. build.py reads their PNG header for width and height. They display at 34 px high (30 on phones) and 30 px in the footer.
- The build checks existence and manifest freshness (a replaced logo-gold.png without a rerun fails, verified).

6. Favicon
- Replace flow/assets/img/logo-emblem.png: a square transparent PNG, currently 256x256. A non-square one is centred on a transparent square.
- Run python3 tools/make_favicon.py. It writes:
  - flow/favicon.ico with 48, 32 and 16 px sizes, each downscaled in two steps and unsharp-masked
  - assets/img/favicon-32.png and favicon-16.png
  - assets/img/apple-touch-icon.png: 180x180, the emblem at 82% on #171310, RGB
- The settings.brand.icons paths already point at these files. None of them are in derivatives.json. The .ico link is neither versioned nor checked; the PNG links are versioned and existence-checked.

7. Reel video and poster
- Target spec, measured on the seven committed films:
  - flow/assets/video/<slug>.mp4: 540x960 (9:16), 30 fps, H.264 High profile, yuv420p, no audio stream, moov atom before mdat (faststart), about 0.35 to 0.9 Mbit/s, 0.5 to 0.97 MB for 8 to 14 s.
  - flow/assets/video/<slug>.jpg: 480x854 first-frame poster, 10 to 60 KB.
- The originals were 4K, 60 fps, with sound, 42 to 80 MB each. They stay outside flow/.
- The exact command was not committed. This reproduces the spec:
  ffmpeg -i SRC -an -vf "scale=540:960:force_original_aspect_ratio=increase,crop=540:960,fps=30" -c:v libx264 -profile:v high -pix_fmt yuv420p -crf 26 -preset slow -movflags +faststart OUT.mp4
  ffmpeg -i OUT.mp4 -frames:v 1 -vf scale=480:854 -q:v 5 OUT.jpg
- Add {"product": "<published id>", "video": "assets/video/<slug>.mp4", "still": "assets/video/<slug>.jpg"} to home.json reels.items.
- The build checks that both files exist and nothing else: codec, size and audio are unchecked.

What build.py checks (build.py:1256-1286), so a deploy does not fail:
- (a) Every path passed through V() or PV() must be readable, or it reports 'missing: <path>'. V() covers:
  - flow.min.css, catalogue.js and shop.js
  - brand.logo and logo_light
  - icons.png32, png16 and apple
  - seo.og_image
  - every categories[].image
  - every hero image, plus its -1320, -phone and -phone-750 copies
  - every reel still and video
  PV() covers the originals of published product images.
- (b) For each published product image: the original, -card, -600, -card-360 and -thumb must exist. The last three need a derivatives.json entry whose recorded md5 equals the original's current md5; a missing entry counts as stale ('made from an older photo').
- (c) Every derivatives.json entry whose source still exists must match that source's md5. This catches replaced banners, category photos and logos.
- (d) Every *.html in flow/ must be one of the 11 PAGES or 404.html.
- Not checked: icons.ico, -card freshness, unpublished products' images, image dimensions, alpha, video encoding.
- Implicit crashes (Python traceback, exit 1): a missing edp_data.json (build.py:279), a missing required key, or an unknown usp icon.

## Build and deploy

After an edit:

1. Save content through the storage layer as json.dumps(obj, indent=2, ensure_ascii=False) + "\n". That round-trips products.json, settings.json, copy.json and navigation.json byte for byte. home.json's one-line reels objects will reformat once. Keep a backup per save; flow/content/.backups/ is gitignored and the old admin kept 20 per file there. Validate against the constraints above before writing, because build.py only catches missing media.
2. If media changed, from flow/: python3 tools/make_derivatives.py. Also run tools/make_gold_logo.py first for logo art, and tools/make_favicon.py for the emblem.
3. Rebuild: cd /Users/ajoomama/github/structured-corner-v2/flow && /usr/bin/python3 build.py. It must run inside flow/ because of relative paths. Success prints 'catalogue: 33 products' and 'wrote 11 pages' and exits 0. Failure exits 1 with 'build failed:' and a list, or a traceback. build.py regenerates catalogue.js, the 11 pages, 404.html, robots.txt and flow.min.css (from flow.css) every run. It writes all of them before running its checks, so on failure restore the previous content and rebuild. Never run two builds, or a build and make_derivatives, at once.
4. Reload the preview. server.py sends no-store. Every ?v= token changes on its own because it is a content hash (V() and PV()): edit first, rebuild after.
5. Stale-build check, the same one CI runs: cd flow && python3 build.py && git status --porcelain -- . After committing, it must print nothing.
6. Commit locally, only after checking git status: the tree already carries unrelated uncommitted work. Include:
   - flow/content/*.json
   - new, changed and deleted media under flow/assets/img, flow/assets/cat and flow/assets/video
   - flow/tools/derivatives.json (CI has no Pillow and never makes copies, it only checks them)
   - the regenerated flow/*.html (11 pages plus 404.html), flow/assets/catalogue.js, flow/assets/flow.min.css and flow/robots.txt
   - flow/favicon.ico if the favicon changed
   Never hand-edit the generated files. Repo rules: no attribution trailer, no em dashes.
7. Ask the owner before any git push (standing rule 1).

On a push to main, Netlify (netlify.toml, Python 3.12) and GitHub Pages (.github/workflows/pages.yml) each do the same:
- Run build.py on the committed tree.
- Fail if it exits non-zero or if git status --porcelain -- flow/ is non-empty afterwards: an uncommitted rebuild output, or a referenced file that was never committed.
- Copy flow/*.html, flow/favicon.ico, flow/robots.txt and flow/assets/ (less cat/SOURCES.txt and flow.css) into _site and publish it.

Netlify caches /assets/* for a year as immutable and sends HTML as no-cache.

## Risks

- build.py writes every page, catalogue.js, flow.min.css, 404.html and robots.txt before it runs its checks (build.py:1192-1250, then 1284-1286). A failed build leaves flow/ rewritten in the broken state and the preview shows it. The admin must validate before saving, serialize builds and make_derivatives runs, and restore the previous content and rebuild on failure.
- Wrong types pass the build silently. A decimal or negative price, on the product or a size, renders AED 0 and the bag charges 0 (verified). A boolean stock prints 'True left'. An unknown category, tint or gender, or a reel or CTA pointing at a missing or unpublished product, all build with exit 0. Missing keys, an unknown usp icon, or a missing flow/edp_data.json crash with a Python traceback (build.py:279 reads that file even though HANDOFF says it is not read). The admin needs its own schema validation.
- Many fields the owner will expect to edit are read by nothing: 13 product fields (name_ar, story_ar, family, tone, occasion, season, longevity, sillage, badge, seo_title, seo_description, image_alt, related), all 15 settings.store rules, seo.default_title_suffix and default_description, social, analytics, payments, languages, brand.suffix (tool only), copy.strip, search_placeholder, collection_intros, home.sections, navigation.main and navigation.footer. Showing them as live edits would mislead the owner. Wiring the store rules means touching shop.js recalc and checkout copy, which are the locked engine.
- Visitor-visible text is hardcoded and already contradicts the data. The quiz shows 'AED 89' (build.py:1092) while every EDP is AED 85. Its hardcoded profiles (shop.js:498-525) disagree with products.json gender for 5 of the 9 sprays and say 8 are unnamed, though all 9 have names. The collection 'All' intro is rewritten at runtime to mention 'oud oils, Reserve' (shop.js:890). The homepage 'All 13' and 'All 9' counts and the 'Discovery Trio, AED 129' bands (build.py:509, 515, 558, 1112) will not follow product edits. The hardcoded footer links differ from navigation.json footer.
- Escaping is inconsistent. usp title and sub, all of quiz_banner, and size labels, gender, size and contents (via _meta) go into the pages unescaped at build time. catalogue.js is unescaped twice (unent), and shop.js then inserts story, ingredients, size labels, and names in the bag and gift box with innerHTML. A stray < or " breaks markup, and HTML entities typed into content render differently on build-time and runtime cards. The admin should store plain Unicode text and reject < > and entities.
- HANDOFF.md is stale where an admin would look up enums: its category keys oud-oils/reserve (the real keys are attars, edp, gift-sets, bakhoor), 'edp_data.json not read at build', and navigation.json 'footer', which nothing reads. Take enums from the code: build.py:345-349, 577-583, 1141 and shop.js:766-772.
- Structure is hardcoded. Adding a category needs build.py (_meta, shelves, FACETS_LIVE, CRUMB, PDP data-cats) and shop.js (CAT_LABEL, CAT_INTRO). Renaming a tab label breaks its active state (PAGES fifth column, build.py:1181-1191). Renaming a category label loses its Arabic toggle entry.
- Price and size coupling: size chips change only the displayed price, while the bag charges products.<id>.price (HANDOFF open item 15). Editing a size price without keeping one size equal to product.price shows the wrong preselected chip and charges a price no chip shows.
- Stock does not gate purchases: stock 0 can still be added to the bag and shows 'Only 0 left' on the PDP. An admin inventory field will not make anything sold out without code.
- Publishing footprint: flow/assets is copied to _site wholesale, so any original or temp file written there goes live. Any .html in flow/ fails the build. The earlier flow/admin/ was downloadable from the live site (commit 75c4872). The admin, its uploads staging and its backups belong outside flow/.
- Local exposure: .claude/launch.json's bgs-flow runs 'python3 -m http.server 4310 --directory flow', and flow/server.py binds ('', 4310). Both listen on all interfaces and serve content/ and tools/. An admin with write endpoints on port 4310 has to replace that server, bind 127.0.0.1 only, and reject requests whose Host or Origin is not localhost:4310, or require a per-session token plus a JSON content type. Without that, any web page the owner visits could POST to it (CSRF or DNS rebinding) while there is no login.
- Media gaps the build does not catch. -card.jpg is never freshness-checked, so replacing an original without rewriting its -card serves the old card photo under a new ?v=. make_derivatives removes orphaned -600, -card-360 and -thumb files but not -card. import_website_set.py deletes a product's frames numbered above the new count, and import_new_edits.py deletes <id>-*.jpg outright, so they can clobber admin uploads. make_derivatives rewrites the whole manifest and walks every image, so it must not run concurrently with an upload.
- Product ids are effectively permanent. Carts and wishlists in localStorage (bgs_cart, bgs_wish), shared links, reels, hero CTA hrefs, the hardcoded footer royal-amber links and image filename prefixes all hold them. A renamed id silently empties those bag lines (shop.js:1273).
- The working tree has uncommitted edits (navigation.json, shop.js, flow.css, server.py, HANDOFF.md and the regenerated pages) from other work. The admin's first saves, builds and commits must not sweep them into an unrelated commit.
- A future PostgreSQL store: build.py reads content only through load_content() (a relative 'content' dir, build.py:74-80), but the importers read and rewrite products.json directly (import_website_set.py:159, 239; import_images.py:192, 249; import_new_edits.py:60, 98) and make_gold_logo.py reads settings.json. The storage layer must either keep exporting the five JSON files before each build and tool run, or those tools must change with it. CI builds from the committed JSON, so the files stay the deploy's source of truth either way.
- HEIC photos from a phone cannot be opened by the installed Pillow (no pillow_heif); convert them with macOS sips first or reject them with a clear message. Video encoding and image dimensions are never checked by the build, so the admin must enforce the targets itself.
